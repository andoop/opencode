## تحديد موضع المشروع

هذا المستودع لا يصف أداة برمجة ذكاء اصطناعي سطح مكتب عامة، بل يصف منصة ويب داخلية لأبحاث وتطوير الذكاء الاصطناعي مخصصة من OpenCode.

- إنه منتج داخلي **Web-first**؛ التركيز الحالي للتخصيص هو تطبيق الويب
- يخدم **التعاون متعدد المستخدمين** داخل المنظمة، وليس الاستخدام المحلي لمطور واحد
- لا يسمح بالاتصال بحرية بمجلدات الخادم؛ يعمل المستخدمون ضمن **حدود المشاريع التي يتحكم فيها المسؤول**
- يوفر **قدرات منصة ذكاء اصطناعي موحدة**، وليس مجرد صفحة "محادثة مع الذكاء الاصطناعي لتحرير الكود"

يمكن فهمه على أنه:

> منصة عمل أبحاث وتطوير ذكاء اصطناعي خاضعة للتحكم وقابلة للإدارة ومتعددة المستخدمين للاستخدام الداخلي.

## فلسفتنا

تهدف المنصة إلى أن تصبح منصة تعاون داخلية موحدة لأبحاث وتطوير الذكاء الاصطناعي، وليس مجرد صفحة برمجة بالذكاء الاصطناعي.

المبادئ الأساسية:

- **ليست سطح مكتب بعيد، بل منصة عمل ذكاء اصطناعي ضمن مشاريع خاضعة للتحكم**
- **ليست لقلة من المطورين يحتكرون الذكاء الاصطناعي، بل لمزيد من الأدوار للمشاركة في إنتاج البرمجيات ضمن نطاقهم المصرح به**
- **ليست ذكاء اصطناعي يرد على الأسئلة فقط، بل ذكاء اصطناعي يصبح تدريجياً طبقة التنفيذ في سير عمل الأبحاث والتطوير**
- **ليست إزالة الحدود، بل تحسين الكفاءة تحت حوكمة الصلاحيات والمشاريع والجلسات والنماذج**

من حيث المنتج، الحدود الثلاثة الأهم هي:

- **حد المشروع**: يمكن للمستخدمون العاديون الوصول فقط للمشاريع المسجلة مسبقاً من المسؤولين
- **حد الجلسة**: مهمة واحدة تتوافق مع جلسة ومساحة عمل مستقلتين
- **حد الصلاحيات**: ما يراه المستخدمون وما يمكنهم فعله والنماذج التي يمكنهم استخدامها يتحكم فيها المنصة

## القدرات الرئيسية الحالية

يركز التخصيص على تطبيق الويب:

- التسجيل متعدد المستخدمين وتسجيل الدخول وإدارة الحسابات
- قدرات المستخدمين والمشاريع والنماذج والتدقيق المرئية للمسؤولين
- تسجيل المشاريع لعرض مستودعات الكود المعتمدة فقط
- مساحات عمل معزولة حسب الجلسة، عادة عبر Git worktrees
- حوكمة موحدة للنماذج ومقدمي الخدمة والصلاحيات والأوضاع
- نقطة دخول موحدة لمنصة الذكاء الاصطناعي للفرق

التركيز ليس على سطح المكتب أو TUI، بل على:

> تمكين المستخدمين الداخليين من إكمال الأسئلة والأجوبة والتحليل والتحرير والتنفيذ والتعاون عبر الويب، ضمن مشاريع خاضعة للتحكم.

## متعدد المستخدمين ومنصة الذكاء الاصطناعي الموحدة

المنصة لا تمنح الوصول الكامل لكل من يسجل الدخول. بدلاً من ذلك:

1. يجهز المسؤولون كود المشروع على الخادم
2. يسجل المسؤولون المجلدات المسموح بها كمشاريع
3. يسجل المستخدمون ويدخلون عبر الويب
4. يرى المستخدمون العاديون فقط المشاريع المفتوحة لهم
5. يبدأ المستخدمون العمل في جلسات بعد الدخول إلى مشروع

توفر منصة الذكاء الاصطناعي الموحدة:

- نقطة دخول موحدة للنماذج
- إدارة موحدة لمقدمي الخدمة
- تحكم موحد في الصلاحيات
- سير عمل موحد للجلسات
- حدود موحدة للتدقيق والحوكمة

يدعم هذا التصميم النشر الداخلي التدريجي: البدء بصلاحيات منخفضة المخاطر، ثم التوسع حسب الدور والسيناريو.

## دعم Cursor CLI

تدعم المنصة **Cursor CLI** كمصدر نموذج/مقدم خدمة في منصة الذكاء الاصطناعي الموحدة.

### كيفية الاتصال

يجب أن يكون Cursor CLI مثبتاً على آلة الخادم وأن تكون أمر `agent` متاحاً في shell:

```bash
agent login
```

بعد تسجيل الدخول، تعيد المنصة استخدام حالة تسجيل الدخول المحلية Cursor الموجودة.

### الاستخدام في المنصة

- يتحكم المسؤولون في ما إذا كان المستخدمون يمكنهم الوصول للنماذج ومقدمي الخدمة
- المستخدمون المقيدون افتراضياً عادة لديهم فقط وضع `ask`
- قائمة النماذج البيضاء الافتراضية تتضمن عادة:
  - `cursor-cli/auto`
  - `cursor-cli/composer-1`
  - `cursor-cli/composer-1.5`

إذا لم يكن Cursor CLI مثبتاً أو `agent` غير متاح، فلن تظهر نماذج ومقدمي خدمة Cursor CLI في المنصة.

### توصيات التكوين

للنشر الداخلي الأولي:

- المستخدمون المقيدون افتراضياً: وضع `ask` فقط
- قائمة النماذج البيضاء الافتراضية: تفضيل نماذج `cursor-cli`
- عدم عرض Provider أو Server أو MCP أو إدارة عالية المخاطر الأخرى افتراضياً
- السماح للمسؤولين بتوسيع القدرات حسب المستخدم أو الدور حسب الحاجة

الفوائد:

- تكلفة انضمام منخفضة
- حدود مخاطر واضحة
- مصدر نماذج موحد
- تجربة مستخدم بسيطة للاعتماد الداخلي

### دوره في النظام

مع اتصال Cursor CLI، لا تستدعي المنصة ببساطة واجهة برمجة تطبيقات نموذج خارجية. تجمع سياق الجلسة وحدود المشروع وأدوات المنصة، ثم تمررها إلى Cursor CLI للتنفيذ.

لذا `cursor-cli` ليس أداة معزولة هنا، بل جزء من منصة الذكاء الاصطناعي الموحدة.

## توصيات النشر للمسؤولين

النهج الموصى به:

1. إعداد مجلدات للمشاريع الخاضعة للتحكم
2. تسجيل المستودعات المعتمدة صراحة فقط
3. منح المستخدمين العاديين صلاحيات مقيدة افتراضياً
4. إعطاء الأولوية لأسئلة وأجوبة الويب والقدرات منخفضة المخاطر
5. إضافة المزيد من النماذج والأوضاع ووظائف سير العمل تدريجياً

باختصار: لا تفعّل كل شيء دفعة واحدة. بدلاً من ذلك:

> أنشئ أولاً حدود المشاريع والصلاحيات والنماذج والجلسات، ثم وسّع قدرات المنصة خطوة بخطوة.

## التطوير المحلي

يركز التخصيص على تطبيق الويب، لذا يجب أن يبدأ التطوير المحلي بمكدس الويب.

تثبيت التبعيات:

```bash
bun install
```

بدء تشغيل بأمر واحد:

```bash
sh restart-services.sh
```

العناوين الافتراضية:

- الخلفية: `http://localhost:4096`
- الواجهة: `http://localhost:3000`

لبدء التشغيل بشكل منفصل:

```bash
bun run --cwd packages/opencode dev
bun run --cwd packages/app dev
```
