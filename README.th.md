## การกำหนดตำแหน่งของโปรเจกต์

รีพозиทอรีนี้ไม่ได้อธิบายเครื่องมือ AI coding เดสก์ท็อปทั่วไป แต่เป็นแพลตฟอร์มเว็บ AI R&D ภายในองค์กรที่ปรับแต่งจาก OpenCode

- เป็นผลิตภัณฑ์ภายใน **Web-first** โดยโฟกัสการปรับแต่งปัจจุบันอยู่ที่ Web App
- ให้บริการ **การทำงานร่วมกันหลายผู้ใช้** ในองค์กร ไม่ใช่การใช้งานแบบเดี่ยวของนักพัฒนา
- ไม่อนุญาตให้เชื่อมต่อกับโฟลเดอร์เซิร์ฟเวอร์โดยอิสระ ผู้ใช้ทำงานภายใน **ขอบเขตโปรเจกต์ที่ผู้ดูแลควบคุม**
- ให้ **ความสามารถของแพลตฟอร์ม AI แบบรวม** ไม่ใช่แค่หน้า "แชทกับ AI เพื่อแก้ไขโค้ด"

สามารถเข้าใจได้ว่าเป็น:

> โต๊ะทำงาน AI R&D ที่ควบคุมได้ มีการกำกับดูแล และรองรับหลายผู้ใช้ สำหรับการใช้งานภายในองค์กร

## ปรัชญาของเรา

แพลตฟอร์มมุ่งหมายให้เป็นแพลตฟอร์ม AI R&D ร่วมมือภายในองค์กรแบบรวม ไม่ใช่แค่หน้า AI coding

หลักการหลัก:

- **ไม่ใช่เดสก์ท็อประยะไกล แต่เป็นโต๊ะทำงาน AI ภายในโปรเจกต์ที่ควบคุม**
- **ไม่ใช่เพื่อให้นักพัฒนาจำนวนน้อยผูกขาด AI แต่เพื่อให้บทบาทมากขึ้นมีส่วนร่วมในการผลิตซอฟต์แวร์ภายในขอบเขตที่ได้รับอนุญาต**
- **ไม่ใช่ AI ที่ตอบคำถามเพียงอย่างเดียว แต่เป็น AI ที่ค่อยๆ กลายเป็นชั้นการดำเนินการในโฟลว์ R&D**
- **ไม่ใช่การยกเลิกขอบเขต แต่เป็นการเพิ่มประสิทธิภาพภายใต้การกำกับดูแลสิทธิ์ โปรเจกต์ เซสชัน และโมเดล**

ในแง่ของผลิตภัณฑ์ ขอบเขตที่สำคัญที่สุดสามอย่างคือ:

- **ขอบเขตโปรเจกต์**: ผู้ใช้ทั่วไปเข้าถึงได้เฉพาะโปรเจกต์ที่ผู้ดูแลลงทะเบียนก่อน
- **ขอบเขตเซสชัน**: งานหนึ่งงานสอดคล้องกับเซสชันและพื้นที่ทำงานอิสระหนึ่งชุด
- **ขอบเขตสิทธิ์**: สิ่งที่ผู้ใช้เห็น สิ่งที่ทำได้ และโมเดลที่ใช้ได้ ถูกควบคุมโดยแพลตฟอร์ม

## ความสามารถหลักปัจจุบัน

การปรับแต่งเน้นที่ Web App:

- การลงทะเบียนหลายผู้ใช้ การเข้าสู่ระบบ และการจัดการบัญชี
- ความสามารถผู้ใช้ โปรเจกต์ โมเดล และการตรวจสอบที่ผู้ดูแลเห็นได้
- การลงทะเบียนโปรเจกต์เพื่อเปิดเผยเฉพาะรีพозиทอรีโค้ดที่อนุมัติ
- พื้นที่ทำงานแยกตามเซสชัน โดยทั่วไปผ่าน Git worktrees
- การกำกับดูแลโมเดล ผู้ให้บริการ สิทธิ์ และโหมดแบบรวม
- จุดเข้าแพลตฟอร์ม AI แบบรวมสำหรับทีม

โฟกัสไม่ใช่เดสก์ท็อปหรือ TUI แต่:

> ให้ผู้ใช้ภายในองค์กรทำ Q&A การวิเคราะห์ การแก้ไข การดำเนินการ และการร่วมมือผ่านเว็บ ภายในโปรเจกต์ที่ควบคุม

## หลายผู้ใช้และแพลตฟอร์ม AI แบบรวม

แพลตฟอร์มไม่ให้สิทธิ์เต็มแก่ทุกคนที่เข้าสู่ระบบ แต่:

1. ผู้ดูแลเตรียมโค้ดโปรเจกต์บนเซิร์ฟเวอร์
2. ผู้ดูแลลงทะเบียนโฟลเดอร์ที่อนุญาตเป็นโปรเจกต์
3. ผู้ใช้ลงทะเบียนและเข้าสู่ระบบผ่านเว็บ
4. ผู้ใช้ทั่วไปเห็นเฉพาะโปรเจกต์ที่เปิดให้พวกเขา
5. ผู้ใช้เริ่มทำงานในเซสชันหลังจากเข้าสู่โปรเจกต์

แพลตฟอร์ม AI แบบรวมให้:

- จุดเข้าโมเดลแบบรวม
- การจัดการผู้ให้บริการแบบรวม
- การควบคุมสิทธิ์แบบรวม
- โฟลว์งานเซสชันแบบรวม
- ขอบเขตการตรวจสอบและการกำกับดูแลแบบรวม

การออกแบบนี้รองรับการเปิดตัวภายในองค์กรแบบค่อยเป็นค่อยไป: เริ่มด้วยสิทธิ์ความเสี่ยงต่ำ แล้วขยายตามบทบาทและสถานการณ์

## การสนับสนุน Cursor CLI

แพลตฟอร์มรองรับ **Cursor CLI** เป็นแหล่งโมเดล/ผู้ให้บริการในแพลตฟอร์ม AI แบบรวม

### วิธีเชื่อมต่อ

เครื่องเซิร์ฟเวอร์ต้องติดตั้ง Cursor CLI และคำสั่ง `agent` ต้องมีใน shell:

```bash
agent login
```

หลังเข้าสู่ระบบ แพลตฟอร์มจะใช้สถานะการเข้าสู่ระบบ Cursor ในเครื่องที่มีอยู่เดิม

### การใช้งานในแพลตฟอร์ม

- ผู้ดูแลควบคุมว่าผู้ใช้สามารถเข้าถึงโมเดลและผู้ให้บริการได้หรือไม่
- ผู้ใช้ที่ถูกจำกัดตามค่าเริ่มต้นมักมีเฉพาะโหมด `ask`
- รายการโมเดลไวต์ลิสต์ตามค่าเริ่มต้นมักรวม:
  - `cursor-cli/auto`
  - `cursor-cli/composer-1`
  - `cursor-cli/composer-1.5`

หาก Cursor CLI ไม่ได้ติดตั้งหรือ `agent` ไม่พร้อมใช้งาน โมเดลและผู้ให้บริการ Cursor CLI จะไม่ปรากฏในแพลตฟอร์ม

### คำแนะนำการกำหนดค่า

สำหรับการเปิดตัวภายในองค์กรครั้งแรก:

- ผู้ใช้ที่จำกัดตามค่าเริ่มต้น: เฉพาะโหมด `ask`
- รายการโมเดลไวต์ลิสต์ตามค่าเริ่มต้น: เลือกโมเดล `cursor-cli`
- ไม่เปิดเผย Provider, Server, MCP หรือการจัดการความเสี่ยงสูงอื่นๆ ตามค่าเริ่มต้น
- ให้ผู้ดูแลขยายความสามารถตามผู้ใช้หรือบทบาทตามความจำเป็น

ประโยชน์:

- ต้นทุนการติดตั้งต่ำ
- ขอบเขตความเสี่ยงชัดเจน
- แหล่งโมเดลรวม
- UX เรียบง่ายสำหรับการนำไปใช้ภายในองค์กร

### บทบาทในระบบ

เมื่อเชื่อมต่อ Cursor CLI แล้ว แพลตฟอร์มไม่ได้เรียก API โมเดลภายนอกอย่างเดียว แต่รวบรวมบริบทเซสชัน ขอบเขตโปรเจกต์ และเครื่องมือแพลตฟอร์ม แล้วส่งไปยัง Cursor CLI เพื่อดำเนินการ

ดังนั้น `cursor-cli` ตรงนี้ไม่ได้เป็นเครื่องมือแยก แต่เป็นส่วนหนึ่งของแพลตฟอร์ม AI แบบรวม

## คำแนะนำการเปิดตัวสำหรับผู้ดูแล

แนวทางที่แนะนำ:

1. เตรียมโฟลเดอร์โปรเจกต์ที่ควบคุม
2. ลงทะเบียนเฉพาะรีพозиทอรีที่อนุมัติอย่างชัดเจน
3. ให้สิทธิ์จำกัดตามค่าเริ่มต้นแก่ผู้ใช้ทั่วไป
4. ให้ความสำคัญกับ Q&A เว็บและความสามารถความเสี่ยงต่ำ
5. ค่อยๆ เพิ่มโมเดล โหมด และฟังก์ชันโฟลว์งานมากขึ้น

สรุป: อย่าเปิดใช้งานทุกอย่างพร้อมกัน แต่:

> สร้างขอบเขตโปรเจกต์ สิทธิ์ โมเดล และเซสชันก่อน แล้วค่อยขยายความสามารถแพลตฟอร์มทีละขั้น

## การพัฒนาในเครื่อง

โฟกัสการปรับแต่งอยู่ที่ Web App ดังนั้นการพัฒนาในเครื่องควรเริ่มสแต็กเว็บ

ติดตั้ง dependencies:

```bash
bun install
```

เริ่มต้นด้วยคำสั่งเดียว:

```bash
sh restart-services.sh
```

URL ตามค่าเริ่มต้น:

- Backend: `http://localhost:4096`
- Frontend: `http://localhost:3000`

เพื่อเริ่มต้นแยกกัน:

```bash
bun run --cwd packages/opencode dev
bun run --cwd packages/app dev
```
